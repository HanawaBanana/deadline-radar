Every analysis is stored in a local sqlite3 file (deadline_radar.db). Nothing leaves the machine.

How it works

  1. Read. An offline rules reader, or a language model, proposes values with a quote from the page.
  2. Validate. Deterministic code re-parses every date, checks every number against the page, and drops anything it cannot find.
  3. Report. What survived becomes the brief and the .ics calendar; what did not is listed with the reason.

Missing fields are reported as “{{MISSING_TEXT}}” rather than guessed.
